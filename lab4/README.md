# Лабораторная работа №4. Многопроцессный веб-сервер

`webd` раздаёт статические файлы по HTTP/1.0 и HTTP/1.1. Родительский процесс вызывает `accept()` и для каждого принятого соединения создаёт потомка через `fork()`. Потомок закрывает слушающий сокет, отвечает клиенту и завершает работу через `_exit()`. Родитель закрывает свою копию клиентского сокета, а завершившихся потомков собирает через `waitpid()` по сигналу `SIGCHLD`.

Сервер поддерживает `GET` и `HEAD`. Для запроса к `/` он отдаёт `index.html`. Ответ содержит тип файла, длину в байтах и `Connection: close`. Путь разрешается внутри корневого каталога сайта через `openat()`. Компоненты `.` и `..` отклоняются, переход по символическим ссылкам запрещён.

## Сборка и запуск

Из корня репозитория выполните:

```sh
cd lab4
make
pid=$(./webd)
```

По умолчанию демон слушает `127.0.0.1:8080` и раздаёт файлы из `www`. При успешном запуске команда печатает PID демона. Аргументы `-a IPv4` и `-p PORT` задают адрес и порт. Необязательный последний аргумент задаёт корневой каталог сайта.

Чтобы работать на переднем плане, запустите `./webd -f -p 8081 www`. Ошибки пишутся через `syslog` с тегом `webd`. В режиме `-f` сообщения также выводятся в терминал. На Debian журнал можно посмотреть командой `journalctl -t webd`.

## Проверка

```sh
url=http://127.0.0.1:8080
tmp=$(mktemp -d)

curl -fsS "$url/hello.txt" -o "$tmp/hello.txt"
cmp www/hello.txt "$tmp/hello.txt"
curl -fsS "$url/sample.png" -o "$tmp/sample.png"
cmp www/sample.png "$tmp/sample.png"

curl -I "$url/sample.png"
curl -i "$url/missing"
seq 1 20 | xargs -P 8 -I '{}' curl -fsS -o /dev/null "$url/sample.png?request={}"

kill -TERM "$pid"
rm -r "$tmp"
```

`cmp` подтверждает побайтовое совпадение обоих файлов. Для PNG запрос `HEAD` возвращает `200 OK`, `Content-Type: image/png` и `Content-Length: 164`. Запрос отсутствующего файла возвращает `404 Not Found` и создаёт запись в журнале.

При проверке на macOS восемь клиентов одновременно держали открытыми соединения с незавершёнными заголовками. Для каждого соединения был виден свой дочерний процесс. Пока эти процессы ожидали данные, сервер успешно отдал PNG ещё двенадцати параллельным клиентам. После закрытия соединений все потомки были собраны.
