# Лабораторная работа 4. Файлы и файловая система UNIX

## Упражнение 4.1. Изучение структуры файловой системы

- При помощи следующих команд: pwd, cd, ls отработайте основные операции навигации в файловой системе:
  - Перейдите в корневой каталог.
  - Спускаясь по дереву каталогов, пройдитесь по основным каталогам и подкаталогам, и ознакомьтесь с их содержанием.
  - Зафиксируйте структуру иерархии файловой системы и назначение основных каталогов:
  
`pwd` - print working directory, выводит абсолютный путь текущего рабочего каталога
![01 pwd.png](fig/01%20pwd.png)

`cd` - change directory, смена директорий
```bash
cd /              # перейти в корень
cd home/          # перейти в home/ 
cd ..             # подняться на уровень выше 
cd                # перейти в домашний каталог (то же самое, что cd ~)
cd -              # вернуться в предыдущий рабочий каталог
```
![01 cd.png](fig/01%20cd.png)

`ls` - list, выводит список файлов
```bash
ls           # список файлов текущего каталога
ls -l        # подробный формат (права, владелец, размер, дата)
ls -a        # включая скрытые файлы (начинающиеся с точки)
ls -la /home/vlad  # оба флага сразу, для конкретного каталога
```
![01 ls -la home-vlad.png](fig/01%20ls%20-la%20home-vlad.png)

Абсолютный путь — начинается от корня, однозначен независимо от текущего положения: `/home/vlad/file.txt`

Относительный путь — отсчитывается от текущего рабочего каталога: `../vlad/file.txt`, `./script.sh`

**Иерархия файловой системы (FHS — Filesystem Hierarchy Standard)**


| Каталог      | Описание                                                                                                                                                                 |
|:-------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **`/`**      | Корень файловой системы — вершина всего дерева                                                                                                                           |
| **`bin/`**   | Основные пользовательские команды/утилиты, необходимые в однопользовательском режиме                                                                                     |
| **`sbin/`**  | Системные утилиты для администрирования (требуют обычно root)                                                                                                            |
| **`boot/`**  | Файлы, необходимые для загрузки системы: ядро, конфигурация загрузчика GRUB                                                                                              |
| **`dev/`**   | Файлы устройств (device files) — интерфейс к оборудованию через файловую систему (диски, терминалы)                                                                      |
| **`etc/`**   | Конфигурационные файлы системы и приложений (passwd, shadow, fstab, hostname и др.)                                                                                      |
| **`home/`**  | Домашние каталоги пользователей (`/home/vlad`)                                                                                                                           |
| **`root/`**  | Домашний каталог суперпользователя root (вынесен отдельно от `home/` — важно для доступности при проблемах)                                                              |
| **`lib/`**   | Общие библиотеки, необходимые программам из `/bin` и `/sbin`                                                                                                             |
| **`media/`** | Точки монтирования съёмных носителей (USB, CD/DVD), обычно автоматически при подключении                                                                                 |
| **`mnt/`**   | Временные точки монтирования, добавляемые вручную администратором                                                                                                        |
| **`opt/`**   | Дополнительное стороннее ПО, устанавливаемое не через пакетный менеджер дистрибутива                                                                                     |
| **`proc/`**  | Виртуальная файловая система — предоставляет доступ к информации о работающих процессах и параметрах ядра (не хранится физически на диске, генерируется ядром «на лету») |
| **`sys/`**   | Виртуальная файловая система — интерфейс к устройствам и драйверам ядра                                                                                                  |
| **`run/`**   | Временные runtime-данные с момента загрузки системы (PID-файлы, сокеты) — очищается при каждой перезагрузке                                                              |
| **`tmp/`**   | Временные файлы, доступные всем пользователям на запись, часто очищается при перезагрузке                                                                                |
| **`usr/`**   | Основная часть пользовательского ПО и данных «только для чтения»: `/usr/bin`, `/usr/lib`, `/usr/share`, `/usr/local` — по объёму обычно самый большой каталог в системе  |
| **`var/`**   | Переменные данные, изменяющиеся в процессе работы системы: логи (`/var/log`), кэши, базы данных пакетного менеджера                                                      |
| **`srv/`**   | Данные сервисов, предоставляемых системой                                                                                                                                |

## Упражнение 4.2. Типы файлов

1. Для экземпляров различных типов файлов:

- обычный файл (/etc/fstab, /bin/bash, /usr/bin/apropos)
- каталог (/tmp)
- специальный файл устройства (/dev/sda, /dev/tty1)
- именованный канал (/run/systemd/initctl/fifo)
- сокет (/run/systemd/journal/dev-log)
- символическая ссылка (/dev/cdrom)

Примечание: при отсутствии файлов из перечня найдите аналог соответствующего типа.

2. Запишите особенности отображения различных типов файлов командой ls -l:
```bash
# Обычный файл (regular file)
# Содержит произвольные данные: текст, бинарный исполняемый код, изображение и т.д
vlad@debian13:/$ ls -l /etc/fstab /bin/bash /usr/bin/apropos
-rwxr-xr-x 1 root root 1412096 мая  9 13:58 /bin/bash
-rw-r--r-- 1 root root     921 сен  7 21:56 /etc/fstab
lrwxrwxrwx 1 root root       6 мая  2  2025 /usr/bin/apropos -> whatis

# Каталог (directory)
# Каталог — это специальный файл, содержащий таблицу соответствий «имя файла → номер inode» для файлов, лежащих в нём.
# Без флага `-d` `ls -l /tmp` покажет содержимое каталога, а не информацию о самом каталоге как файле. 
vlad@debian13:/$ ls -l -d /tmp
drwxrwxrwt 7 root root 140 сен 16 00:51 /tmp

vlad@debian13:/$ ls -l /tmp
итого 0
drwx------ 3 root root 60 сен 15 22:04 systemd-private-35666f0257834e85a9ad83301cd6f517-systemd-logind.service-L8T61Z

# Специальный файл устройства (device file)
# блочные устройства (block device, b) — работа идёт блоками данных произвольного доступа, типично для дисков /dev/sda
# символьные устройства (character device, c) — посимвольный/потоковый доступ, типично для терминалов, последовательных портов: /dev/tty1
vlad@debian13:/$ ls -l /dev/sda /dev/tty1
brw-rw---- 1 root disk 8, 0 сен 15 22:04 /dev/sda
crw------- 1 root tty  4, 1 сен 15 22:04 /dev/tty1

# Именованный канал / FIFO (named pipe)
# Механизм межпроцессного взаимодействия (IPC) - позволяет одному процессу писать данные, а другому читать их в порядке 
# очереди FIFO, при этом оба процесса не обязаны быть родственными
vlad@debian13:/$ ls -l /run/systemd/initctl/fifo
ls: невозможно получить доступ к '/run/systemd/initctl/fifo': Нет такого файла или каталога
# найденный аналог /dev/initctl, /run/initctl
vlad@debian13:/$ ls -l /dev/initctl
lrwxrwxrwx 1 root root 12 сен 15 22:04 /dev/initctl -> /run/initctl
vlad@debian13:/$ ls -l /run/initctl
prw------- 1 root root 0 сен 15 22:04 /run/initctl

# Сокет (socket)
# Тоже механизм IPC, но более гибкий, чем FIFO — поддерживает двунаправленную связь и модель клиент-сервер
vlad@debian13:/$ ls -l /run/systemd/journal/dev-log
srw-rw-rw- 1 root root 0 сен 15 22:04 /run/systemd/journal/dev-log

# Символические ссылки
# Символическая ссылка (симлинк, symlink или soft link) — это специальный тип файла в UNIX/Linux, который содержит 
# внутри себя не данные, а текстовый путь к другому файлу или каталогу.
vlad@debian13:/$ ls -l /dev/cdrom
lrwxrwxrwx 1 root root 3 сен 15 22:04 /dev/cdrom -> sr0
```
**Расшифровка вывода**


| Символ  | Тип                      |
|:--------|:-------------------------|
| **`-`** | обычный файл             |
| **`d`** | каталог                  |
| **`b`** | блочное устройство       |
| **`c`** | символьное устройство    |
| **`p`** | именованный канал (FIFO) |
| **`s`** | сокет                    |
| **`l`** | символическая ссылка     |


3. Используя команды: stat, file исследуйте метаданные и содержимое различных типов файлов (из шага 1):

- Команда `stat` — детальные метаданные
![stat etc-fstab.png](fig/stat%20etc-fstab.png)
  - Ключевые поля:
    - Size — размер в байтах
    - Device, Inode — идентификатор устройства и номер inode (уникальный номер файла в пределах файловой системы)
    - Links — количество жёстких ссылок на этот inode
    - Access/Uid/Gid — права доступа и владелец
    - три временные метки:
      - Access (atime) — время последнего чтения файла;
      - Modify (mtime) — время последнего изменения содержимого;
      - Change (ctime) — время последнего изменения метаданных (прав, владельца, имени) — важно не путать с mtime: ctime меняется даже без изменения содержимого, например при chmod.

- Команда `file` — определение содержимого
![file bin-bash.png](fig/file%20bin-bash.png)

`file` пытается определить природу содержимого файла, анализируя его сигнатуру

Для разных типов файлов file покажет разное:
  - обычный текстовый файл: ASCII text
  - исполняемый бинарник: ELF 64-bit LSB executable... с указанием архитектуры
  - каталог: directory
  - символьное устройство: character special
  - символическая ссылка: symbolic link to sr0.

## Упражнение 4.3. Манипулирование объектами дерева каталогов UNIX

При помощи следующих команд: `touch`, `mkdir`, `rmdir`, `cp`, `mv`, `rm`, `ln`, `mkfifo`, `mknod` отработайте основные операции работы с файловой системой, зафиксируйте полученные результаты:
- перейдите в домашний каталог пользователя:
```bash
cd ~
```
- получите информацию о текущем рабочем каталоге:
```bash
vlad@debian13:~$ pwd
/home/vlad
vlad@debian13:~$ 
```
- получите информацию о содержимом текущего каталога:
```bash
vlad@debian13:~$ ls -la
итого 48 
```
![03 ls -la.png](fig/03%20ls%20-la.png)

- создайте новый подкаталог subdir в текущем каталоге:
```bash
vlad@debian13:~$ mkdir subdir
vlad@debian13:~$  
```
- перейдите в него:
```bash
vlad@debian13:~$ cd subdir/
vlad@debian13:~/subdir$  
```
- создайте в данном подкаталоге новый файл myfirstfile:
```bash
vlad@debian13:~/subdir$ touch myfirstfile
vlad@debian13:~/subdir$  
```
- создайте мягкую symblink и жесткую hardlink ссылки на него:
```bash
vlad@debian13:~/subdir$ ln -s myfirstfile mysoftlink 
vlad@debian13:~/subdir$ ln myfirstfile myhardlink
vlad@debian13:~/subdir$  
```

| Критерий                          | Символическая ссылка (`-s`)                            | Жёсткая ссылка                                                         |
|:----------------------------------|:-------------------------------------------------------|:-----------------------------------------------------------------------|
| **Что хранит**                    | Путь (текстовую строку) к файлу-цели                   | Ничего — это второе имя того же inode                                  |
| **Отдельный inode**               | Да, собственный                                        | Нет, тот же номер inode, что у оригинала                               |
| **Через границы файловых систем** | Может указывать куда угодно, включая другой раздел     | Только внутри одной файловой системы (один и тот же раздел/устройство) |
| **На каталог**                    | Может (широко используется)                            | Обычно запрещено (кроме `.` и `..`, создаваемых ядром)                 |
| **При удалении оригинала**        | Ссылка "ломается" (dangling link) — указывает в никуда | Файл продолжает существовать, пока жива хотя бы одна ссылка            |

- переместите и/или скопируйте файл myfirstfile в вышележащий каталог:
```bash
cp myfirstfile ../myfirstfile_copy 
mv myfirstfile ..                      
```
`cp` создаёт новый, независимый файл, `mv` - переименование записи в каталоге

- удалите оставшиеся файлы:
```bash
vlad@debian13:~/subdir$ rm mysoftlink myhardlink
vlad@debian13:~/subdir$ 
```
- перейдите в вышележащий каталог и удалите созданный вами подкаталог subdir и файл myfirstfile:
```bash
vlad@debian13:~/subdir$ cd ..
vlad@debian13:~$ rmdir subdir
vlad@debian13:~$ rm myfirstfile
vlad@debian13:~$  
```
- Разница между rm и rmdir:
  - `rmdir` удаляет только пустой каталог, если внутри что-то осталось, вернёт ошибку Directory not empty. Это защитная мера от случайного удаления содержимого
  - `rm` без флагов удаляет обычные файлы, но не может удалить каталог напрямую. Для удаления каталога вместе с содержимым используется `rm -r` (рекурсивно), `-f` (force, без подтверждений): `rm -rf subdir`

- создайте именованный канал myfifo:
```bash
vlad@debian13:~$ mkfifo myfifo
vlad@debian13:~$  
```
![03 echo.png](fig/03%20echo.png)

- создайте образ оптического диска, находящийся в накопителе /dev/cdrom:
```bash
dd if=/dev/cdrom of=~/cdimage.iso bs=2048 status=progress 
```
if (input file) — источник, в данном случае файл устройства /dev/cdrom 
of (output file) — файл назначения, куда будет записан образ
bs (block size) — размер блока за одну операцию чтения/записи, 2048 байт — стандартный размер сектора для CD/DVD 
status=progress — вывод прогресса копирования

```bash
vlad@debian13:~$ sudo dd if=/dev/cdrom of=~/cdimage.iso bs=2048 status=progress
dd: не удалось открыть '/dev/cdrom': Носитель не найден
vlad@debian13:~$ 

vlad@debian13:~$ dd if=/dev/zero of=~/test_image.img bs=1M count=10
10+0 records in
10+0 records out
10485760 bytes (10 MB, 10 MiB) copied, 0,0103278 s, 1,0 GB/s
vlad@debian13:~$ 
```

## Упражнение 4.4. Поиск файлов

При помощи следующих команд: `find`, `whereis`, `which` отработайте основные операции поиска файлов, зафиксируйте полученные результаты:
- найдите в каталоге `/usr` все файлы размером больше 800Кb 

`find` обходит дерево каталогов, начиная с указанной точки, и проверяет каждый встреченный файл на соответствие заданным критериям. Это самый мощный, но и самый медленный способ
```bash
find /usr -type f -size +800k 
```
