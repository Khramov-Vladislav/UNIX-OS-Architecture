## Упражнение 5.1. Владельцы файлов

1. Зафиксируйте права доступа к файлу и владельцев файлов из Шаг 1 упр. 4.2, лаб. 4:

Каждый файл в UNIX-системе имеет двух владельцев, хранящихся в его inode:

* владелец-пользователь (owner/user, UID) — обычно тот, кто создал файл
* владелец-группа (group, GID) — по умолчанию основная группа создавшего пользователя

2. При помощи команд: chown, chgrp попробуйте подарить файлы из домашнего каталога пользователя student пользователю
   vinnie, группе root. Зафиксируйте реакцию системы:
   `chown` - change owner, смена владельца-пользователя
   ![01 chown.png](fig/01%20chown.png)

Вариации команды

```bash
sudo chown vinnie:root файл       # владелец = vinnie, группа = root
sudo chown :root файл             # только группа (эквивалент chgrp)
sudo chown -R vinnie каталог      # рекурсивно для каталога и всего содержимого
```

Обычный пользователь не может передать файл другому пользователю через `chown`, даже если он сам владеет этим файлом.
Причина — защита от злоупотребления системой учёта дискового пространства: если бы это было разрешено, пользователь мог
бы создавать огромные файлы, а затем «дарить» их другим пользователям, обходя ограничения на использование диска,
либо подбрасывать файлы от чужого имени в обход контроля происхождения. Поэтому менять владельца файла на другого
пользователя разрешено только root (или через sudo от лица root).

`chgrp` - change group, смена владельца-группы

![01 chgrp.png](fig/01%20chgrp.png)

Меняет только группу-владельца файла. Правила здесь мягче, чем у `chown` для смены пользователя:

* root может установить любую группу для любого файла
* обычный пользователь может сменить группу файла, которым он владеет, но только на одну из групп, в которых он сам
  состоит

## Упражнение 5.2. Права доступа к объектам файловой системы UNIX

1. Создайте новый файл newfile. Зафиксируйте права доступа к файлу и владельцев полученного файла:

![02 newfile.png](fig/02%20newfile.png)

Каждый файл имеет три уровня прав доступа — для владельца (owner), группы (group) и всех остальных (others), каждый
уровень состоит из трёх битов:

* r (read) — чтение
* w (write) — запись
* x (execute) — исполнение (для файлов) или право входа/просмотра содержимого (для каталогов).

Когда программа создаёт новый файл, она запрашивает у ядра максимальные права, которые считает разумными по умолчанию:

* для обычных файлов — базовое значение 666 (rw-rw-rw-) — файлы по умолчанию не создаются исполняемыми, это защитная
  мера
* для каталогов — базовое значение 777 (rwxrwxrwx), поскольку каталогам бит x необходим для входа в них.

Однако реальные права окажутся меньше базового значения — из-за действия umask.

2. При помощи команды: umask:

`umask` — маска отмены прав

- просмотрите и зафиксируйте значение реверсной маски прав доступа по умолчанию для вновь создаваемых файлов

```bash
vlad@debian13:~$ umask
0002 
```

При маске `0002` новые файлы и каталоги будут иметь следующие права по умолчанию:

* Новые папки: 775 (drwxrwxr-x) — владелец и группа могут читать, записывать и открывать папку, а остальные — только
  читать и открывать.
* Новые файлы: 664 (-rw-rw-r--) — владелец и группа могут читать и редактировать файлы, а остальные — только читать.

- установите значение реверсной маски прав доступа по умолчанию в 000. Создайте файл defaultfile. Зафиксируйте права
  доступа к файлу и владельцев полученного файла:

`umask 000` — ничего не отнимается

```bash
mask 000
vlad@debian13:~$ touch defaultfile
vlad@debian13:~$ ls -l defaultfile 
-rw-rw-rw- 1 vlad vlad 0 сен 20 14:13 defaultfile
vlad@debian13:~$ 
```

Права файла совпадут с базовыми (666), потому что маска не отнимает ничего — читать и писать в файл сможет любой
пользователь системы.

- установите значение реверсной маски прав доступа по умолчанию в 777. Создайте файл maskedfile. Зафиксируйте права
  доступа к файлу и владельцев полученного файла:

`umask 777` — отнимается всё

```bash 
ad@debian13:~$ umask 777
vlad@debian13:~$ touch maskedfile
vlad@debian13:~$ ls -l maskedfile 
---------- 1 vlad vlad 0 сен 20 14:16 maskedfile
vlad@debian13:~$ 
```

Все биты прав отняты полностью — файл окажется недоступен вообще никому, включая самого владельца (владелец файла всегда
может выполнить chmod на своём файле, независимо от текущих r/w/x битов, так как это регулируется не правами доступа, а
самим фактом владения).

`umask` действует только на текущий сеанс shell — при новом входе в систему значение вернётся к тому, что задано в
конфигурационных файлах (/etc/profile, ~/.bashrc и т.п.)

3. При помощи команды: chmod отработайте основные операции изменения владельцев и прав доступа к файлам:

`chmod` - change mode, прямое изменение прав

Есть два способа задания прав: числовой (octal) и символьный (symbolic).

```bash
# Числовой способ
# Прямо задаёт итоговые права в восьмеричном виде
chmod 600 privatefile

# Символьный способ
# Символьный способ удобен, когда нужно изменить отдельный бит, не трогая остальные
chmod u+x file        # добавить право исполнения владельцу (user)
chmod g-w file        # убрать право записи у группы
chmod o=r file        # установить ровно "только чтение" для остальных (others)
chmod a+r file        # добавить чтение всем (all = u+g+o)
```

- создайте в домашнем каталоге файл privatefile и установите права доступа rw- --- ---:

```bash
# Только владелец может читать и писать, группа и остальные не имеют вообще никакого доступа.
vlad@debian13:~$ touch privatefile
vlad@debian13:~$ chmod 600 privatefile
vlad@debian13:~$ 
```

- создайте в домашнем каталоге файл publicfile и установите права доступа rw- r-- r--:

```bash
# Владелец может читать/писать, группа и остальные — только читать.
vlad@debian13:~$ touch publicfile
vlad@debian13:~$ chmod 644 publicfile
vlad@debian13:~$ 
```

- создайте в домашнем каталоге новый каталог groupsubdir и установите права доступа rw- r-- ---:

```bash 
kdir groupsubdir
vlad@debian13:~$ chmod 640 groupsubdir
vlad@debian13:~$ 
```

Права `rwx rw- -w-` не включают бит `x` ни для кого. Для каталога бит `x` означает право входить в каталог (выполнять
`cd`
внутрь него)
и обращаться к файлам по имени внутри. Без `x` даже при наличии `r` пользователь сможет получить список имён файлов
внутри каталога (если `r` есть),
но не сможет обратиться к самим файлам (не сможет сделать `cd` туда или прочитать конкретный файл по полному пути).

- создайте в домашнем каталоге новый каталог publicdir и установите права доступа rw- rw- rw-:

```bash
vlad@debian13:~$ mkdir publicdir
vlad@debian13:~$ chmod 666 publicdir
vlad@debian13:~$ 
```

Здесь тоже нет бита `x` ни `у` кого, включая владельца. Значит, даже сам владелец не сможет войти в этот каталог,
несмотря на то, что технически может читать/писать список файлов в нём на уровне метаданных.

```bash
vlad@debian13:~$ cd publicdir
-bash: cd: publicdir: Отказано в доступе
vlad@debian13:~$ 
```
